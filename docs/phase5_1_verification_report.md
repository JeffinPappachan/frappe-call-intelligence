## 3. Security Verification

### A. `/api/models` Endpoint ([`src/server.py:268-321`](file:///e:/Hash/src/server.py#L268-L321))
- **Exposure of Secrets:** NO. Secret keys (`AI_API_KEY`) and HTTP `Authorization` headers are completely stripped. Only the safe dictionary fields `id`, `owned_by`, and `active` are returned.
- **Authentication & Header Validation:** Protected via `x_admin_token: Optional[str] = Header(None, alias="X-Admin-Token")`. If `settings.admin_api_token` is configured and the client token is missing or mismatched, it immediately raises `HTTP 401 Unauthorized`.
- **Safe Fallback:** If in `mock_mode` or no external AI key is set, returns a static curated whitelist (`openai/gpt-oss-20b`, `llama-3.3-70b-versatile`, `whisper-large-v3`) without calling external networks.
- **Upstream Timeouts & Errors:** Wrapped in `try...except httpx.RequestError` with a 10-second timeout, returning a sanitized `HTTP 502 Bad Gateway` ("Error communicating with upstream AI model provider") without leaking tracebacks.

### B. CORS Configuration ([`src/server.py:38-46`](file:///e:/Hash/src/server.py#L38-L46), [`src/config.py:40-44`](file:///e:/Hash/src/config.py#L40-L44))
- **Wildcard Check:** NO wildcard `*` origin with credentials.
- **Configuration Loading:** Loaded directly from `settings.allowed_origins`.
- **Default Allowed Origins:**
  ```python
  allowed_origins: list[str] = [
  ```

## 6. Categorized Findings

### Medium Severity
1. **[SEC-06] Audio Upload Endpoint Lacks File Size & Content-Type Validation**
   - **File:** [`src/server.py:110-123`](file:///e:/Hash/src/server.py#L110-L123)
   - **Details:** `/api/v1/telephony/process-audio` accepts `UploadFile` without checking maximum file size (e.g., 25MB Whisper limit) or validating `file.content_type` (e.g., ensuring `audio/wav`, `audio/mpeg`, `audio/mp4`). A large upload could cause memory exhaustion on small server instances.
   - **Recommended Fix:** Add a 25MB check on `file.size` or `len(audio_bytes)` and validate against allowed MIME types.

2. **[REL-02] Timeline Comment HTTP Status Ignored in Client Call**
   - **File:** [`src/frappe_client.py:293-295`](file:///e:/Hash/src/frappe_client.py#L293-L295)
   - **Details:** `add_timeline_comment` catches failures, but `res = await client.post(...)` does not call `res.raise_for_status()`, returning a boolean `return res.status_code == 200`.

3. **[REL-03] In-Memory Idempotency Store is Process-Bound and Unbounded**
   - **File:** [`src/pipeline.py:38-58`](file:///e:/Hash/src/pipeline.py#L38-L58)
   - **Details:** `InMemoryIdempotencyStore` uses a Python dictionary without a TTL or maximum size eviction policy. For high-volume production, an external Redis or SQLite store with TTL is recommended.

### Low Severity
1. **[DI-04] Telecaller Substring Matching Heuristic**
   - **File:** [`src/frappe_client.py:233-245`](file:///e:/Hash/src/frappe_client.py#L233-L245)
   - **Details:** User email resolution hardcodes substring checks for `"john"`, `"sarah"`, `"emily"`, `"jeffin"`. Other telecallers fall through to checking `"@" in agent_id` or `None`.
